# Объяснение кода model/model.py

Документ объясняет код простым языком для человека без ML-бэкграунда.

## Что делает файл в целом

Файл решает задачу в 2 этапа:

1. Находит подходящие микрокатегории по ключевым фразам с помощью TF-IDF и n-грамм (2-3 слова подряд).
2. Считает вероятности, нужно ли делать дополнительные черновики по этим категориям, через нейросеть (трансформер + softmax).

Дополнительно файл умеет:

- загружать словарь категорий и датасет,
- обучать модель,
- считать метрики качества,
- формировать ответ в формате хакатона.

## Разбор по блокам

### 1) Импорты и проверки зависимостей

Строки: 1-39

- Подключаются стандартные модули Python (`csv`, `json`, `ast`, `Path`, `dataclass`).
- Внешние библиотеки (`torch`, `sklearn`, `transformers`) загружаются «мягко» через `_optional_import`.
- Если библиотека нужна в конкретном месте и не установлена, функции `_require_torch`, `_require_sklearn`, `_require_transformers` дают понятную ошибку с командой установки.

Зачем это нужно:

- Чтобы файл можно было импортировать даже без тяжелых зависимостей,
- и падать только в момент, когда пользователь реально запускает функционал, требующий этих библиотек.

### 2) Структуры данных

Строки: 41-77

- `MicroCategory`: одна микрокатегория (id, название, ключевые фразы).
- `Item`: одно входное объявление.
- `LabeledItem`: объявление + правильные ответы из датасета.
- `Draft`: один сгенерированный черновик.
- `PredictionResult`: результат предсказания модели.

Зачем это нужно:

- Типизированные структуры делают код понятным и снижают количество ошибок.

### 3) Вспомогательный парсер списков

Строки: 80-98

Функция `_parse_int_list` превращает разные форматы в `List[int]`:

- уже готовый список,
- строку вида `[101, 102]`,
- строку вида `101,102` или `101;102`.

Зачем это нужно:

- В CSV и JSONL поля могут быть записаны по-разному, а коду нужен единый тип.

### 4) Загрузка словаря и датасета

Строки: 101-175

- `load_microcategories_from_csv`: читает справочник микрокатегорий.
- `load_labeled_items_csv`: читает размеченный датасет из CSV.
- `load_labeled_items_jsonl`: читает то же из JSONL.
- `split_dataset`: делит выборку на `train/val/test`.

Зачем это нужно:

- Получить входные данные в удобной форме для обучения и оценки.

### 5) TF-IDF ретривер кандидатов

Строки: 178-241

Класс `TfidfMicroCategoryRetriever`:

- Создает TF-IDF векторизатор с n-граммами `(2, 3)`.
- `fit`: обучается на ключевых фразах словаря.
- `detect`: для текста объявления находит наиболее похожие микрокатегории.

Выход `detect`:

- список `detected mcId`,
- словарь оценок похожести (`score_map`).

Зачем это нужно:

- Быстро отсеять нерелевантные категории и оставить разумный набор кандидатов.

### 6) Нейросеть для вероятностей split

Строки: 244-295

Класс `TransformerSoftmaxSplitModel`:

- Текст кодируется трансформером (`AutoModel`).
- Каждая микрокатегория имеет обучаемый вектор (`nn.Embedding`).
- Сходство «текст-категория» дает логит.
- Через softmax получаем вероятности по кандидатам.

Зачем это нужно:

- Не просто искать слова, а учитывать контекст фразы: отдельная услуга или часть комплексного ремонта.

### 7) Единый пайплайн

Строки: 298-480

Класс `DraftSplitPipeline` объединяет все этапы.

Что делает конструктор:

- принимает словарь микрокатегорий,
- создает и обучает TF-IDF ретривер,
- поднимает нейромодель,
- задает порог вероятности `prob_threshold`.

#### Обучение: `train_step` (строки 331-393)

- На входе батч текстов, кандидаты, целевые split-категории, source категории.
- Строится «мягкое» целевое распределение:
    - если есть несколько целевых категорий, вес делится поровну;
    - если целевых нет, масса уходит в source категорию.
- Считается `KLDiv` loss и делается шаг оптимизатора.

Почему так:

- Задача мульти-лейбл (может быть несколько правильных split-категорий).

#### Подготовка кандидатов: `build_candidates` (строки 395-404)

- Берет детект из TF-IDF.
- Гарантирует наличие source категории.
- Опционально принудительно добавляет цели (для устойчивого обучения).

#### Обучение по датасету: `train_on_labeled_items` (строки 406-430)

- Идет по эпохам и батчам,
- формирует входы,
- вызывает `train_step`,
- сохраняет историю loss.

#### Инференс вероятностей: `score_candidates` (строки 432-446)

- Для текста и списка кандидатов возвращает словарь `mcId -> вероятность`.

#### Генерация текста черновика: `_generate_draft_text` (строки 448-451)

- Делает простой шаблон текста черновика из названия категории и фрагмента исходного описания.

#### Финальный прогноз: `predict` (строки 453-480)

- Находит кандидатов (TF-IDF).
- Считает вероятности (softmax).
- Оставляет категории выше порога.
- Формирует `should_split`, `drafts`, `probabilities`.

### 8) Приведение к формату ответа

Строки: 483-496

`to_response_json` возвращает структуру в формате задания:

- `detectedMcIds`
- `shouldSplit`
- `drafts`

### 9) Метрики качества

Строки: 499-529

`evaluate_split_quality` считает:

- `precision_micro`
- `recall_micro`
- `f1_micro`
- `should_split_accuracy`

Как считается:

- `TP` — правильно предсказанные split-категории,
- `FP` — лишние,
- `FN` — пропущенные,
- отдельно accuracy для булевого `shouldSplit`.

## Простой сценарий использования

1. Загрузи словарь категорий:

- `micro = load_microcategories_from_csv("data/rnc_mic_key_phrases.csv")`

2. Загрузи датасет:

- `items = load_labeled_items_csv("data/rnc_dataset.csv")`
- `parts = split_dataset(items)`

3. Создай пайплайн:

- `pipeline = DraftSplitPipeline(microcategories=micro)`

4. Обучи:

- создать optimizer из `torch.optim` и вызвать `train_on_labeled_items(parts["train"], optimizer, ...)`

5. Оцени:

- `metrics = evaluate_split_quality(pipeline, parts["val"])`

6. Запусти предсказание на одном объявлении:

- `result = pipeline.predict(item)`
- `response = to_response_json(result)`

---

## Важно помнить

- TF-IDF этап — быстрый фильтр кандидатов.
- Нейросеть решает более тонкий вопрос «делить или не делить» по смыслу текста.
- Качество сильно зависит от порогов (`tfidf_threshold`, `prob_threshold`) и выбранной трансформер-модели.
